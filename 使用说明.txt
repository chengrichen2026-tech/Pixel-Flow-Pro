Pixel Flow v0.3.22｜使用说明
文档更新：2026-10-14
适用：Chrome / Edge，macOS / Windows

1. 工具结构与能力

Pixel Flow 是 Chrome / Edge 本地扩展，用一张无限画布组织图片、文字、任务和结果。可以普通生图、容器批量生成、分块放大，并让 AI 通过结构化命令执行这些动作。

画布层

图片、文字、图片容器、普通生图任务、图片放大任务、图片或文字结果。连线决定任务输入，结果回到任务右侧。

执行层

GPT Web 本机/团队、Team Cloud、API 四条执行链路。API 使用本机 Worker；团队模式使用远端任务箱与执行服务。

数据层

当前浏览器本地保存画布、资产与 TaskRun 运行记录。提示词库、产品素材、参考图库和模板提供复用入口。

AI 接入层（可选）

本机 Bridge + MCP 让 Codex 读写真实画布、启动任务、查询终态和下载结果。手动操作不需要 Bridge。

2. 先选择生图方式

GPT Web · 本机

当前浏览器登录并能正常使用 chatgpt.com。使用当前账号的图片生成能力；不需要 API Key 或 API Worker。

GPT Web · 团队

提交电脑保存成员令牌；团队至少一台已配对、已登录 ChatGPT 且正在接单的网页生图机。提交电脑不用配对成执行机，与 Team Cloud 共用成员每日额度池。

Team Cloud

保存成员令牌，选择 Flare 或 Sunburst；由团队远端服务执行，不需要登录 ChatGPT，也不需要提交电脑安装 API Worker。

API

准备可用于 aihub.rbmanon.cn 的对应模型 API Key、Node.js 20+ 和本机 API Worker。可选 GPT Image 2 / Sunburst 2.5 / Flare 2.5，不需要登录 ChatGPT 网页。

默认规则：普通新任务在已配置团队成员时默认 GPT Web · 团队，否则默认 API；普通 API 模型默认 GPT Image 2。新建图片放大任务独立默认 API Sunburst，也可以手动选其他模式。已有任务保持已保存的配置。

费用与额度按所选通道和账户规则计算。放大由多个分块请求组成；倍率越高、分块越多，用量和等待时间通常越多。

3. 安装与更新

- 完整解压下载包；源代码下载用户应先按项目说明完成构建。

- Chrome 打开 chrome://extensions，Edge 打开 edge://extensions。

- 开启开发者模式，选择“加载已解压的扩展程序”，指向 扩展程序/ 文件夹。

- 点击工具栏 Pixel Flow 图标打开画布。更新文件后，在扩展管理页重新加载，再刷新画布。

这份说明页可以双击离线阅读；工具的 index.html 需要通过扩展安装入口运行。重新加载正在生成的任务前，先看任务状态；能恢复已保存的对话或 Job 不代表所有中断都可自动恢复。

4. 普通生图：第一次操作

- 上传、拖入或粘贴图片，也可新增文字节点。

- 选中输入图片，点击底部“新增任务”；或从输入节点右侧连线到任务左侧。多张普通图片会作为同一个任务的参考输入。

- 选择主模式与二级选项：GPT Web 的本机/团队、Team Cloud 的 Flare/Sunburst、API 的三种模型。

- 填写提示词。需要配置时，从顶部“生图设置”保存对应 Key 或成员令牌。

- 点击“运行任务”，等待结果写回右侧，查看内容后下载。

TaskRun 是每次运行的权威状态：排队、准备、上传/发送、等待接单、生成、写回、完成、失败、待手动处理、取消。活动任务可取消，失败/取消后可重试；有保留团队 Job 时可“恢复结果”。普通任务可能收到文字回复，要确认结果是所需图片；命令受理、网页出现图片和图片已写回画布是不同阶段。

5. 图片放大：默认 API Sunburst

- 选中一张图片或生成结果，点击底部“新增图片放大任务”。

- 选择 2× / 4× / 8×；默认 2×、API Sunburst。确认 Sunburst 2.5 对应 Key 已保存，API Worker 已运行。

- 点击“开始放大”。工具按原图像素和目标倍率自动带重叠分块，逐块生成，再拼合完整 PNG；无需编辑提示词或手工切图。

- 任务卡只显示紧凑缩略图，全部展开。紫色细框：生成中；红色：失败；完成：中性 1px 细框，不着色。

- 双击某块缩略图只重新生成该块；其他成功块不变。成功后重新拼合，更新原大图节点。运行中禁用重生，失败时保留旧预览与旧大图。

- 整体任务 completed 后，检查结果并下载任务右侧的大图。

倍率指宽和高分别放大：1000×1000 的 2×目标为 2000×2000。当前目标上限为 6400 万像素、最长边 16384px、最多 256 块；超限会明确提示。

工具校验每块实际像素尺寸，并保留原图透明通道。AI 增强会补充细节，产品结构、文字和 Logo 仍需要与原图对照验收；扩尺寸完成不等于商业质量已通过。

6. 画布、容器与批量

- 顶部切换、新建、重命名、管理画布；画布名称可就地编辑。

- 拖动节点、框选；滚轮/双指滑动平移，触控板捏合缩放，左下控制按钮也可缩放或适配视图。

- Command/Ctrl+C、V 复制粘贴图片、结果、容器和任务；任务副本保留输入与配置并重置运行状态。单选图片/结果还能复制真实图片到其他应用。

- Delete/Backspace 删除选中节点；Command/Ctrl+Z 撤销。编辑文本时快捷键作用于文本。

- 点击输入线可断开，节点保留。“节省内存”释放可安全关闭的任务网页并保留对话地址。

图片容器

选中多图创建容器，连接到普通任务后，每张图生成一个子任务；容器外的输入图作为共享参考。可只重试失败项。容器内图可拖出或移出，容器支持内部复制。跨应用多图剪贴板受系统限制，不保证变成多个独立附件。

图片放大只接一张图；批量逐图生成用图片容器。

7. 提示词、素材、图库与模板

- 左侧提供提示词库、产品素材、参考图库、生图模板。

- 提示词可替换或追加到选中任务，也可拖成文字节点。素材可拖入画布，或连接到选中任务/加入选中容器。

- 各库维护名称、标签与示例图，分别导出/导入；导入应选择对应库类型。

- 正式模板入口在左侧模板库，可组合文案、构图、背景、补充、输入图片、模式和 1–4 张输出；模板任务独立运行，失败项可单独重试。

- 底部“生图模版”仍是开发中占位入口。

8. 生图设置与 API 模型

从顶部“生图设置”进入。个人 API 分为 GPT Image 2、Sunburst 2.5、Flare 2.5 三个 Key 字段；选用哪个模型，就保存该模型可用的 Key。没有对应 Key 时，手动任务会引导打开设置，AI 任务需查看返回错误。

显示模型 | API 标识 | 用途 |

GPT Image 2 | gpt-image-2 | 普通 API 任务默认项 |

Sunburst 2.5 | gpt-image-2.5-sunburst | 图片放大默认优先项 |

Flare 2.5 | gpt-image-2.5-flare | 可手动选择 |

模型标识对应本工具使用的 API 网关；Key 还需具备该模型的调用权限。不同字段不会自动互相借用 Key。

团队设置

提交任务的电脑保存成员令牌，可查看在线执行机数。只有承担网页生成的电脑需要在“本机作为网页生图执行机”配对，配对后可开始/暂停接单或解除配对；设备名称由团队任务箱统一设置。团队成员令牌与设备令牌用途不同。

9. API Worker 与 AI Bridge

API Worker：43129

为 API 生图提供持久本机任务执行；API 模式需要它，GPT Web 本机不需要它。

macOS：在项目根目录运行 npm run api-worker:install 尝试常驻安装；如启动失败，可用 node api-worker/server.mjs 手动启动并保持终端打开。

Windows：npm run api-worker:install:windows 安装登录自启，npm run api-worker:start:windows 手动启动，npm run api-worker:uninstall:windows 卸载；更新安装会检查并替换旧 Pixel Worker。

Bridge：43128

供 AI 调用真实画布，普通手动使用可不安装。在项目根目录运行 npm run bridge:install，检查用 npm run bridge:status；同时打开 Pixel Flow 画布。

Bridge 和 API Worker 是不同服务。ready=false 通常需要检查画布连接，不代表 API 网关失败。

健康检查

macOS / Linux：
curl --noproxy '*' http://127.0.0.1:43129/health

Windows PowerShell：
Invoke-RestMethod http://127.0.0.1:43129/health

确认 ok=true、service=pixel-flow-api-worker、workerVersion=2 且 apiModels 包含所需模型。启动命令返回不等于服务健康；当前电脑的后台进程运行正常，也不等于登录自启已通过。API 超时后先检查网关调用记录，再决定是否重试。

10. AI 结构化调用

AI 可读取状态、导入图片、建立连线、创建/执行任务、放大图片、单块重生、查询 TaskRun、恢复已有团队结果和下载大图。操作默认走 MCP → 本机 Bridge → 真实扩展。

- pixel_flow_upscale_image：图片节点、本地绝对路径、Data URL 或 assetId 四选一，一步创建并默认启动放大；默认 API Sunburst、2倍。

- pixel_flow_get_upscale_task：查询 status、progress、tiles、目标尺寸及 finalResults。只有 completed 才提供新成品；重生期间旧图在 previousResults。

- pixel_flow_regenerate_upscale_tile：指定 taskId、tileId 单块重生。

- 当前通用 pixel_flow_execute 也支持 image.upscale；专用工具在新聊天/刷新 MCP 连接后挂载。

{
"op": "image.upscale",
"sourceNodeId": "实际图片节点ID",
"scale": 2,
"generationMode": "api",
"apiImageModel": "gpt-image-2.5-sunburst"
}

写入必须带唯一 requestId 和刚读取的 expectedRevision。命令受理不是完成；继续查询 completed 与 finalResults，再用最终 nodeId 下载。相同 requestId 用于重放同一请求；参数变化使用新 ID。超时先查原请求与画布，不盲目重复生图。

详细参数见 COMMAND_API.md，放大边界与验收见 IMAGE_UPSCALING.md。

11. 保存、备份与数据范围

画布、独立图片和运行记录保存在当前扩展的本地 IndexedDB；各资产库独立导出/导入。重新构建或重载不主动清空本地画布，删除扩展前应先保存必要资料。

当前画布备份范围：打包当前画布、连线、独立图片与最终结果；容器内部图片及放大中间分块结果未完整打包。跨电脑迁移时，需要另行保留原图、各库导出和成品，并先做恢复验证。

个人 API Key、成员令牌和设备令牌由生图设置保存；个人 Key 在 API 请求时传给本机 Worker 和网关，不进入画布备份。团队应用级访问配置/凭证可能随构建提供，与个人授权令牌不同；公开发布按明确授权范围处理，不把用户画布、素材和日志带入公开包。

API 模式把提示词与参考图发送到配置的 API 网关；团队模式把输入发送到团队任务箱/执行服务。GPT Web 使用已有浏览器登录态；工具不会替代登录、验证码或账户额度处理。

12. 常见问题与完成检查

API Sunburst 放大没有启动

检查 Sunburst 2.5 对应 Key、模型调用权限、API Worker 的健康与 apiModels；查看任务具体错误。普通 GPT Image 2 的 Key 字段不会自动替代 Sunburst 字段。

某块红框，或想修正某个分块

等待整体任务结束或先取消，再双击目标块；仅该块重新生成，成功后更新原大图。运行中不重复提交。无需整体再生成一遍。

已经完成，但要确认质量

核对目标像素、图片内容、产品结构、文字/Logo、接缝及透明边缘。任务终态说明执行链路已结束，不代替人工质量验收。

团队任务等待上线、或结果已生成却没写回

等待上线时检查执行机是否配对、在线且接单。结果已存在时优先“恢复结果”，避免重复生成与用量。

更新后界面或模型列表没变

确认加载目录是本次构建的扩展程序，重新加载扩展并刷新画布；模型报旧 Worker 时检查 workerVersion/apiModels。

GPT Web 需要手动处理

按具体提示完成登录、验证码或额度处理。先查看已保存的真实对话和任务状态，再决定恢复或重试。

AI 工具没出现或 Bridge 未连接

打开 Pixel Flow 画布，检查 Bridge 状态；新 MCP 工具在新聊天或刷新连接后加载。当前通用 execute 可调用已有底层命令。

容器复制、备份和跨设备迁移

容器内部复制可用，多图粘贴到外部应用受系统限制。迁移按备份范围说明另行保留原图、库导出和成品，不只保留一个画布文件。
