Pixel Flow v0.3.15｜使用说明
==============================

Pixel Flow 是 Chrome / Edge 本地扩展，用无限画布组织图片、文字、生图任务和结果。
本说明对应 v0.3.15，更新于 2026-09-15。

一、三个模式
------------

任务卡只显示三个主模式，并按需要显示一个二级选择：

1. GPT Web
   - 执行位置可选“本机”或“团队”。
   - 本机使用当前浏览器已登录的 chatgpt.com，不需要 API Key 或 API Worker。
   - 团队即原 Team Web：由已配对、已登录 ChatGPT 且正在接单的网页生图机执行。
   - 团队中任意一台在线执行机都可接单，提交电脑不需要配对成执行机。
   - GPT Web 团队任务不消耗 Team Cloud 每日额度。
   - 没有在线执行机时，团队任务会保留并显示“等待上线”。

2. Team Cloud
   - 模型可选 Flare 或 Sunburst。
   - 只需要团队提供的成员令牌；任务箱地址已内置，平台访问 Key 由安全中继托管。
   - 伙伴不需要 ChatGPT / Codex 账号。

3. API
   - 模型：gpt-image-2。
   - 需要 aihub.rbmanon.cn 的 API Key、Node.js 20+ 和 Pixel Flow API Worker。
   - 不需要登录 ChatGPT 网页。

二、安装或更新扩展
------------------

Chrome：
1. 完整解压下载包。
2. 打开 chrome://extensions。
3. 开启“开发者模式”。
4. 点击“加载已解压的扩展程序”，选择“扩展程序”文件夹。
5. 固定“Pixel Flow｜像素流”图标。

Edge：
1. 打开 edge://extensions。
2. 开启“开发人员模式”。
3. 点击“加载解压缩的扩展”，选择“扩展程序”文件夹。

更新已有安装：替换文件后，必须在扩展管理页点击一次“重新加载”，再刷新 Pixel Flow 和正在使用的 ChatGPT 页面。

三、第一次运行任务
------------------

1. 点击 Pixel Flow 图标打开画布。
2. 上传图片、拖入图片，或按 Command/Ctrl+V 粘贴。
3. 新建任务，把图片或文字节点连接到任务卡左侧。
4. 在任务卡选择 GPT Web、Team Cloud 或 API；GPT Web 再选本机/团队，Team Cloud 再选 Flare/Sunburst。
5. 输入提示词，点击“运行任务”。
6. 根据任务卡状态等待：排队 → 准备 → 上传/发送 → 生成 → 写回 → 完成。
7. 结果会出现在任务右侧；图片右上角可下载。

同一任务完成后再次运行会创建新的运行次数。ChatGPT Web 会优先继续已保存的真实对话；重试不会把旧终态直接改回运行中。

四、任务状态与操作
------------------

- 排队中：等待本机调度名额。
- 准备执行环境：正在准备 Worker 或 ChatGPT 页面。
- 上传参考图 / 发送任务：正在传递输入。
- 等待执行机接单 / 等待上线 / 执行机忙：团队任务已保存，但远端尚未开始生成。
- 正在生成：provider 已开始处理。
- 正在写回：结果正在下载、校验并写入画布。
- 等待手动处理：需要完成 ChatGPT 登录、验证码、额度提示或手动发送。
- 已完成：结果资产、节点和连线已经写入画布。
- 运行失败：显示具体原因，可点击重试。
- 已取消：本次运行已结束，可重新运行。

活动任务可点击“取消”。团队任务若云端稍后完成且仍保留 Job，任务卡会显示“恢复结果”，用于取回已有结果，不重新生图。

五、画布操作
------------

- 双指平行滑动：平移画布；双指并拢/张开：缩放。
- 框选或点击：选择节点。
- Backspace / Delete：删除选中节点；编辑文字时只删除文字。
- Command/Ctrl+Z：撤销当前画布的最近动作。
- Command/Ctrl+C、Command/Ctrl+V：复制粘贴图片、结果、容器或任务。
- 单张图片/结果复制：同时写入系统剪贴板，可粘贴到其他应用。
- 点击输入实线后再点“断开”：只断开这条输入，不删除节点。
- “节省内存”：关闭可安全释放的 ChatGPT 任务标签，同时保留对话地址。
- “备份画布”：保存当前画布、连线和图片数据。

六、图片容器与批量任务
----------------------

1. 选中一张或多张图片，点击“新建图片容器”。
2. 把容器连接到任务。
3. 容器内每张图片会成为一个独立子任务。
4. 容器外同时连接到任务的图片会作为每个子任务的共享参考图。
5. 已完成子项不会因其他子项失败而重跑；可只重试失败项。

容器支持画布内复制。受系统剪贴板和目标应用限制，不能保证把容器中的多张图片一次粘贴成多个独立附件。

七、提示词、素材、图库和模板
----------------------------

- 左侧图标栏依次进入提示词库、产品素材、参考图库和生图模板。
- 提示词可替换或追加到选中任务，也可拖到画布。
- 产品图和参考图可拖入画布，或点击连接到当前选中任务。
- 各库可以维护名称、标签和图片，并分别导出、导入。
- 生图模板可组合文案、构图、背景和自由补充，选择比例、三个主模式及对应二级选项、产品图、参考图和 1–4 张输出。
- 模板生成的任务相互独立，失败项可单独重试。
- 底部“生图模版”按钮仍是开发中提示；正式模板入口在左侧生图模板库。

八、生图设置
------------

点击顶部“生图设置”：

- 个人 API：保存或清除 API Key。
- 团队成员：只保存成员令牌；可查看共享执行机在线数量。
- 本机作为网页生图执行机：仅承担接单的电脑需要配对。
- 网页生图执行机：填写一次性配对码，配对后可暂停接单、开始接单或解除本机配对。

设置弹窗的标题和底部按钮固定，中间内容可滚动；矮窗口下仍能访问全部设置。

九、API Worker
--------------

macOS：运行 npm run api-worker:install。

Windows：
- 安装登录自启：npm run api-worker:install:windows
- 手动启动：npm run api-worker:start:windows
- 卸载：npm run api-worker:uninstall:windows

Windows 安装只使用当前用户启动目录，不需要管理员权限。API 请求最多等待 7 分钟；超时会明确失败，不会自动重复计费。

十、常见问题
------------

- 更新后仍是旧界面：在扩展管理页点击“重新加载”，再刷新画布。
- Bridge 显示 ready=false：先确认 Pixel Flow 画布页面已经打开。
- ChatGPT Web 等待手动处理：打开任务卡的真实对话，完成登录、验证码或手动发送。
- Team Web 一直等待上线：确认至少一台网页生图机处于在线且“正在接单”状态。
- API 请求失败：确认 API Worker 健康、Key 有效，并查看任务卡具体错误。
- 团队任务已在云端完成但画布失败：优先使用任务卡“恢复结果”或结构化恢复命令，不要直接重新生图。
- 不能双击 index.html 使用：必须通过浏览器扩展管理页加载“扩展程序”目录。

十一、数据和隐私
----------------

- 画布、图片和运行记录保存在当前扩展的本地 IndexedDB。
- API Key、团队凭证和网页生图机令牌只保存在当前浏览器本地。
- ChatGPT 密码、Cookie 和登录态不会上传到团队任务箱。
- API Key 模式会把提示词和参考图发送到 aihub.rbmanon.cn。
- Team Cloud / Team Web 会把任务输入发送到配置的团队任务箱。
- 工具不会绕过登录、验证码、套餐或使用次数限制。
- 删除扩展前先备份画布和各资产库。

十二、Codex 结构化操作（可选）
--------------------------------

- 普通手动使用不需要 Bridge。
- 让 Codex 操作真实画布：在 Pixel Flow 项目目录运行 npm run bridge:install。
- Bridge 只监听 127.0.0.1:43128。
- MCP 可读取画布、管理画布和任务、执行/恢复任务、读取 TaskRun、导入库和下载图片。
- 所有写操作使用唯一 requestId 和最近状态的 expectedRevision，写后继续回读。
- 详细命令见 COMMAND_API.md。

推荐优先打开“先看这里-使用说明.html”查看图文版。
